# A09 security review · Agent connection (agent ↔ server, runs stored server-side)

**Date:** 2026-11-15 · **Reviewer:** A09 · **Branch:** `phase5/foundation`
**Range read:** server `8f99210` (contracts/agent/v1 schemas), `13f7443` (Agent and Proving modules, `/agent/v1/*`, run pages), `9266f8d` (tests), `da6cc9b` (contracts.md "Agent connection notes"); Go client `cba1cb1` (yaml.v3) and `47b5d76` (`pair`, `agent`, `agentapi`, `agentstate`, `render/hosted.go`), plus the code they call (`guard`, `execute`, `plan`, `render/text.go`, Identity account deletion, Workspace claim).
**Read against:** threat model S-1, S-2, S-3, S-4, TM-13, TM-16, TM-17, TM-20, TM-35, TM-36, TM-37, TM-40, TM-42, TM-43, RE-1, NAME-4, ADR-010 §4/§6/§11, DL-2; slice 3 review S3-16.

Exploit detail is kept in the private notes, not here.

## Verdict

**BLOCK** for releasing the connected mode (remote runs from the browser) until AC-1 is fixed. The server side can stay merged on this branch.

AC-1 is a High finding in the Go client. Values taken from a captured body are substituted into probe commands that run through the system shell. The current quoting does not hold in common command layouts, and on Windows it does not hold at all. Remote runs make this reachable by anyone who can get a capture into a project, which the product is designed to allow. The flaw also exists in local `webhooktrap test` (`4ace71c`), but there the person picks their own captures in their own terminal. The fix is small and local to the client.

Six Medium findings (AC-2 to AC-7) must be closed before hosted go-live. The Low findings are small fixes for A06 and A08.

## What is right

- **Pairing code (S-1).** 10 Crockford base32 symbols from `random_int` (50 bits), 10-minute TTL, single use, one live code per workspace. Codes are stored as HMAC-SHA-256 under a dedicated key, which is never `APP_KEY`, must be at least 32 bytes, and makes pairing fail closed when missing. Every bad code gets the same `invalid_code`. There is a per-address limit (IPv4 /32, IPv6 /64; 10 per 10 min, then a 1-hour block), a global breaker with a report, and the per-code void as a secondary control. Tests cover the uniform error, HMAC-only storage and the address block.
- **Authentication (S-3, TM-33).** The nonce is 32 random bytes, bound to the agent id, valid 60 s, and deleted by the same `DELETE … RETURNING` that reads it. Single use therefore holds under concurrency. The signed message is length-prefixed and includes the server's canonical origin, so a signature made for one origin fails at another (tested). Unknown agent ids get a nonce too. Access tokens are `wt_agt_` + 40 base62, stored as SHA-256, and last 15 minutes. Revocation and RE-1 expiry are checked on every request. Expired tokens and nonces are purged every minute.
- **`needs_reconfirm` gating (RE-1, TM-42).** Until local confirmation, an agent gets only `confirm`, `decline`, self-unpair and authentication. `hello`, jobs, accept, abort, capture fetch, observations, final and its broadcast channel are all refused, so no mirrors are stored and no counts are returned. Unconfirmed agents are revoked 10 minutes after `pair`, both lazily and by the maintenance job. A claim moves agents with `needs_reconfirm` set and server approvals cleared, and the client clears its local approvals when it reconfirms.
- **Job and capture isolation (TM-35, TM-37).** Every job and run endpoint locks the row and checks `agent_id` against the authenticated agent. Any other job or run answers the same not-found. A capture is served only if the job references it, the job belongs to this agent, and the job is neither expired nor completed. Each fetch is logged per agent (`capture_access_log`, `CaptureFetchedByExecutor`).
- **Observations and final document.** Request schemas are closed, and every string is length- or pattern-bounded. `seq` is idempotent (`insertOrIgnore` on `(run_id, seq)`) and capped. Completed deliveries are immutable. PV-11 is applied server-side before storage, and anything outside PV-2 (or outside PV-5 for an opted owner run) becomes `#invalid`. The final document is first-write-wins on the SHA-256 of the raw body. The server checks the run id, provider, `fail_on`, the type → severity table, recomputed counts, evidence pointing at real deliveries, Level 1 status agreement and EXIT-1.
- **No agent prose shown (TM-16).** The hosted schema has no title, what, why, fix, snippet or citation field. Finding text is rendered from type + pack + params. The only agent-supplied tokens on the run page are pattern-bounded (agent name, probe names, event type, framework token, semver) and are rendered as React text. There is no `dangerouslySetInnerHTML` anywhere in `resources/js`. Run pages are owner-only with a uniform not-found (TM-13, tested).
- **Broadcast auth (TM-20).** A separate endpoint for the agent guard signs only `private-agent.{own id}`, ignores session cookies, and answers a bare 403 to everything else.
- **Go client transport (S-4).** The origin is canonicalised and pinned at pairing, and pairing is refused if the server's echo disagrees. No redirects are followed, whatever client is passed in. System roots and TLS 1.2+ are used, with no `InsecureSkipVerify` on the API client. Every response is size-capped and must carry `"proto": 1`. Tokens are never stored or printed. Jobs are validated before use. Each capture is checked for id, SHA-256 of the decoded body, size, header count and syntax, and JSON depth before the engine sees it. Redacted headers are never re-sent.
- **Local key storage.** The key file is 0600 in a 0700 directory. Group- or world-readable files and directories are refused, and so are symlinks (`Lstat` + regular-file check). There is one key per origin, and the key is deleted on the local N or on unpair.
- **Secrets stay local.** `hello` carries secret *names* only (closed schema, `hint_last4` refused). Probe and reset commands run with secret variables stripped. The final document is checked for secret bytes before it is sent.
- **TTY rules (TM-56).** `agent` has no `--yes`. A first target approval (with the NAME-4 text) and the probe-command confirmation both need an interactive terminal. Otherwise the agent declines with `needs_confirmation` and the run stays Queued. `pair --yes` is refused for a guest workspace. Approvals are keyed on (origin, agent id, scheme, host, port).
- **Target binding.** The server accepts only a declared (scheme, host, port), and the path is ≤ 512 printable ASCII without spaces. The client re-checks against `webhooktrap.yml`, then runs the target guard: provider and metadata hosts are denied and the resolved address is pinned for the dial.

## Findings

| ID | Severity | Area | Finding | Fix |
|----|----------|------|---------|-----|
| AC-1 | **High** | Go client · probe commands | `{{T.id}}` values come from the captured body. The first lookup (pack object id field) is not checked against the pack's `id_pattern`, and two packs have no pattern at all. A non-plain value is wrapped in POSIX single quotes and run with `sh -c`, or with `cmd /C` on Windows. Single-quoting does not protect a value placed inside a double-quoted part of the command, which is the usual way to write SQL in a `psql -c "…"` probe. It does nothing under `cmd.exe`. A crafted capture can therefore change the command the developer's shell runs. Remote runs make this reachable without the developer choosing the payload. | Interpolate a value into a `cmd:` probe only if it matches a strict id charset (`[A-Za-z0-9_-]`, ≤ 128) and the pack's `id_pattern` when one exists, on both lookup paths. Otherwise decline the job (`target_not_allowed`, line "probe value is not a plain id"). Preferred: pass values as environment variables (`WT_ID_<TYPE>`) and document `"$WT_ID_CUSTOMER"` in place of inline templates. On Windows, refuse `cmd:` templates that are not plain ids. Add a hostile-value corpus test covering quoted, unquoted and Windows positions. |
| AC-2 | Medium | Go client · terminal output (S3-16) | The run summary header prints the capture-derived event type without cleaning. The client has three sanitisers (`clean` in `render`, `clean` and `display` in `cmd`), and none covers the full set the server strips (`\p{Cc}`, `\p{Cf}`, U+2028/2029, tag characters). Zero-width characters, soft hyphen and line or paragraph separators get through. | Use one shared sanitiser with the server's `TerminalText` character set. Apply it at print time to every server- and capture-derived string (event type, provider event id, labels, target, probe stderr). Extend the TM-T6 canary corpus to the agent's stdout and stderr. |
| AC-3 | Medium | Server · re-pairing | A newly confirmed agent silently revokes every older confirmed agent of the same name (`replaced`). Names are chosen by the client. Anyone who obtains a live code for a workspace can therefore evict the owner's agent and take its name. The owner keeps seeing "laptop" and keeps sending runs, and with them captures, to it. This defeats the "Not your machine?" check in S-1. | Do not replace silently. Either give a colliding name a suffix (`laptop-2`) and let the owner revoke the old one, or replace only when the owner chose "Replace *laptop*" when issuing the code: the code is bound to that agent id and the browser shows both key fingerprints. Amend schema.md to whichever rule is kept. |
| AC-4 | Medium | Server · account deletion (DL-2) | Agent and Proving register no `AccountDeletionParticipant`, and the TODO in `AccountDeletion::tombstone` is still open. Agents are revoked by an `AccountDeleted` listener *after* the tombstone commits. If that listener fails, agents of a tombstoned account keep authenticating, because agent auth does not check owner liveness. A pairing code issued just before deletion stays usable during the tombstone. Open runs are aborted only through that same post-commit chain. | Add participants. Agent: revoke every agent and delete pairing codes and tokens, inside the tombstone transaction. Proving: abort open runs and complete their jobs. Make `pair` refuse a workspace whose owner is tombstoned. Extend TM-T157 to agents and runs. |
| AC-5 | Medium | Server · long-poll (TM-40) | There are 4 slots for the whole instance and no per-agent or per-workspace cap. One account with a few agents, or one token sending parallel polls, can hold every slot for 25 s at a time. Every other tenant then gets `503 busy`. | Allow one slot per agent: a session advisory lock on the agent id, and a second concurrent poll answers `204` at once. Cap slots per workspace while slots are contended. Have A10 size the pool against HTTP workers, and alert on the 503 rate. Note for A10: session advisory locks need a session-pooled connection (not PgBouncer transaction mode). |
| AC-6 | Medium | Server · final document integrity (S-5, TM-17) | Level 1 consistency is checked against the document's own deliveries, not against the observations already recorded. Completed observation rows are kept and the document's copies are ignored, so the page and the verdict can disagree. `level` is not tied to the finding type, so labelling a Level 1 type as level 2 skips the check. A Level 1 failure with no finding (for example a 2xx on a tampered delivery) is not detected. `finished_at` is taken as sent. As a result, a forged "passed" is accepted. | Compare document deliveries with stored completed observations (status, transport, over_budget) and answer 422 `level1_inconsistent` on any difference. Fix `level` per type, as a table next to `SEVERITY`. Derive the Level 1 findings implied by deliveries and their signing or tamper kinds, and require them in the document. Clamp `finished_at` to [started_at, now]. |
| AC-7 | Medium | Server · detective control (S-1) | No "New agent paired" email is sent for accounts, and no browser path exists to revoke an agent (the account `/agents` pages are not built). A rogue agent can be noticed only in the live pairing toast, and cannot be removed. | Before hosted release: send the account email on `AgentPaired`, and add the browser revoke action with name, OS and key fingerprint. |
| AC-8 | Low | Go client · declines | A non-TTY agent declines with `needs_confirmation`. The server rightly keeps the run Queued, so the next long-poll returns the same job at once and the agent declines again with no pause. This loops until the job expires, with a log line on every iteration. | Remember declined job ids until their `expires_at` and skip them, or back off. Optionally, have the server hold a waiting job back from the same agent until its next `hello`. |
| AC-9 | Low | Go client · abort | The client never calls the new abort endpoint. A failed capture check, a refused final document or a local error leaves the run Running until `agent_lost` (30 min). The hosted document also carries capture event types that the server's `eventType` pattern refuses, so a hostile capture makes the final upload fail with 422. | On these failures, call `abort` with `capture_verification_failed`, `target_unreachable` or `internal_error`. Map event types and provider ids outside the schema charset to a placeholder before upload. |
| AC-10 | Low | Server · terminal text | `jobs/next` returns `requester.workspace_label`, which includes the account's free display name, without `TerminalText::clean`. `pair` and `hello` do clean it. The client strips most, but not all, of these characters (AC-2). | Clean the label in `RunJobs::next` as well. |
| AC-11 | Low | Server · pairing breaker | About 300 failures from distinct addresses (or IPv6 /64s) trip the global breaker. | AC-12 | Low | Server · observation volume | A run accepts up to about 300 batches of up to 1 MiB. | AC-13 | Low | Go client · key storage (S-3) | The key is a plain file. The OS keychain is not used, Windows ACLs are not checked, and the per-origin directory is named by a non-injective slug. | AC-14 | Info | Server · pair command | The default `AGENT_PAIR_COMMAND` is `webhooktrap agent pair …`, but the CLI is `webhooktrap pair …`. Pasting the command fails closed. | Change the default to `webhooktrap pair {code} --server {origin}`. |

The secret check runs on the final document only, not on observation batches or the plan. Probe-command confirmation is keyed on the file hash for all workspaces. This is acceptable once AC-1 is fixed. | Match the server's path charset. Ignore proxies for dev origins. Run the secret check on every upload. |

## Decisions on the open questions

1. **Capture fetch before accept.** **Accepted**, so the agent can plan locally. Conditions, all met on the server today: the agent is confirmed, the job is this agent's and still open (a decline other than a waiting decline closes it), and every fetch is logged per agent. Two client conditions also apply. Fetched bytes are neither printed nor fed to probe templates before the local approval. AC-1 is fixed before remote runs ship. A06 should surface the per-agent fetch log on the run page or in the account audit once those pages exist.
2. **Re-pairing, same-name replacement.** **Rejected as implemented** (AC-3). Names stay unique among confirmed agents, but a collision is resolved by a suffix or by an owner-chosen replacement bound to the code, never silently. schema.md is amended to the chosen rule.
3. **`0.0.0-dev` refused with 426.** **Keep 426** on hosted and on self-host in production: R55 is the lever for pushing security fixes, and a dev build has no known provenance. For local development, allow a config switch (for example `AGENT_ALLOW_DEV_BUILDS`) that is honoured only when `APP_ENV` is `local` or `testing`. It should log a warning on each accepted handshake and never apply to `min_agent_version` checks of release builds. Alternatively, stamp dev builds with a real version through `-ldflags`.
4. **New abort endpoint.** **Accepted.** It is limited to the owning agent, an accepted job and a Running run, uses enumerated reasons, ends the run Aborted with exit 2 and no document, and closes the job (and so capture fetch). It is serialised with `final` by the run row lock. The client must use it (AC-9).
5. **Account deletion.** **Not acceptable as is** (AC-4). Agents, pairing codes, tokens and open runs must be handled by participants inside the tombstone transaction (DL-2).
6. **`--insecure-dev-origin` scope.** **Accepted as implemented.** It applies only at `pair`, only for `localhost`, `*.localhost`, `*.test` and loopback addresses, and stored origins are re-validated. Add a warning on every `agent` start for an `http://` origin, and refuse it when the server reports `kind: hosted`.
7. **Pairing.** Entropy, HMAC, the uniform error and the per-address limits meet S-1. The breaker is accepted with AC-11. Phishing surface: the client prints the origin it connected to and a cleaned label, and the S-2 question is asked (and is mandatory for guests). Account labels include a self-chosen display name, so the label is a hint, not an identity. The detective control is missing (AC-7).
8. **Server-rendered findings.** TM-16 holds: no agent prose is stored for display or shown.
9. **Long-poll slot cap.** Fails closed with 503 + `Retry-After`, and slots are freed on worker death. The fairness gap is AC-5.

## Tests to add (A11)

- AC-1: hostile template values (quoted, unquoted and `cmd.exe` positions) are declined or passed only through the environment.
- AC-2: the canary corpus (C0, C1, bidi, zero-width, separators, tags) in a capture's event type and ids leaves the agent's terminal output clean.
- AC-3: a second agent with the same name neither revokes nor hides the first unless the owner asked for a replacement.
- AC-4: account tombstone revokes agents, voids pairing codes and aborts open runs in the same transaction, and `pair` with a pre-deletion code fails.
- AC-5: one agent cannot hold more than one slot, and one workspace cannot hold every slot.
- AC-6: a final document whose deliveries differ from recorded observations, with a Level 1 type marked level 2, or omitting an implied Level 1 finding, is refused.
- TM-T20, browser direction: a browser session cannot authorise `private-agent.*`.

**AC-1 reproduction, re-run:** the earlier quoting break no longer reproduces. Values now reach the shell only as `WT_<TYPE>_ID` environment variables, and the command text holds only a reference to the variable written for its quoting context. Validation (plain id of 1 to 128 characters from `[A-Za-z0-9_-]`, plus the pack's `id_pattern`, on both lookup paths) refuses those values before they get that far. A refused value aborts the remote run (`capture_verification_failed`). There are two independent layers, and each one is enough on its own.
