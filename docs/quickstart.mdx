This walkthrough takes a Stripe handler running on your machine from a first captured event to a first finding. You need Node.js (for `npx`) or the [installed binary](/install), and a handler listening on localhost.

<Steps>
  <Step title="Get a capture URL">
    Open the [example run](https://app.webhooktrap.dev/r/example) and press **Get a URL**. This starts a guest session: no account, no email.

    <Frame caption="The example run page. Get a URL starts a guest session.">
      <img src="/images/quickstart-example-get-url.webp" alt="Example run page with the Get a URL button framed in magenta." />
    </Frame>

    You land on **Arrivals** with your capture URL. Copy it.

    <Frame caption="Your capture URL, on the capture host in.webhooktrap.dev.">
      <img src="/images/quickstart-capture-url.webp" alt="Arrivals page waiting for the first delivery, with the capture URL framed." />
    </Frame>

    A guest session lasts 24 hours and holds up to 100 deliveries and 10 runs. The session bar shows the time left and both counts. One hour before the end it says **Ends in 1 h**, and a full quota says **Limit reached**. Sign in from the session bar to keep it: the session moves into your account, with the same URL and deliveries.
  </Step>

  <Step title="Send a webhook to it">
    The waiting panel has instructions per provider. For Stripe: in test mode, open **Developers › Webhooks › Add destination**, paste the URL, pick the events you handle, save, then trigger a test checkout.

    <Frame caption="Provider instructions on the waiting panel.">
      <img src="/images/quickstart-provider-tabs.webp" alt="Waiting panel with tabs for Stripe, GitHub, Shopify, Standard Webhooks and curl." />
    </Frame>

    Any HTTP request works too:

    ```bash
    curl -X POST https://in.webhooktrap.dev/c/YOUR_KEY \
      -H 'Content-Type: application/json' \
      -H 'X-Event-Type: order.paid' \
      -d '{"id":"evt_test_0001","type":"order.paid","data":{"order_id":"ord_1042","amount":2500,"currency":"eur"}}'
    ```

    From your own app, set its webhook or callback URL (often an environment variable such as `WEBHOOK_URL`) to the capture URL and trigger the event.

    The capture URL always answers `200` with `{"received":true}`. See [Capture endpoint](/reference/capture-endpoint).
  </Step>

  <Step title="See it arrive">
    Deliveries appear live. Webhook Trap recognises the provider from its headers and groups related events, here three Stripe events about one subscription.

    <Frame caption="Three Stripe events, grouped by subscription.">
      <img src="/images/quickstart-captures-arrived.webp" alt="Arrivals list with invoice.paid, payment_intent.succeeded and customer.subscription.updated, and the detail of the selected delivery." />
    </Frame>

    The signature shows **Not checked**: your signing secret stays on your machine, so only the agent can check it.
  </Step>

  <Step title="Pair the agent">
    Open **Agent** and press **Pair an agent**. The page shows a code, valid for 10 minutes, and the command to run.

    <Frame caption="A pairing code and its command.">
      <img src="/images/guest-pairing-code.webp" alt="Pair an agent panel with a 10-character code and the npx pair command framed." />
    </Frame>

    Run it in a terminal on the machine where your handler runs:

    ```bash
    npx @webhooktrap/agent@1 pair 7KQ2M-XR9TD --server https://app.webhooktrap.dev
    ```

    The agent prints the server, the workspace, its name and its key fingerprint, then asks `Join? [y/N]`. Answer `y` only if you created the code in your own browser just now.

    <Warning>
      Agent 1.0.0 defaults to `https://webhooktrap.dev` when you leave out `--server`. Always pass `--server https://app.webhooktrap.dev` with 1.0.0. The default changes to the app host in a later release.
    </Warning>
  </Step>

  <Step title="Declare your handler">
    In your project, create `webhooktrap.yml`. The agent only sends to the target declared here.

    ```yaml webhooktrap.yml
    target: http://127.0.0.1:4242/webhooks/stripe
    provider: stripe
    secret: env:STRIPE_WEBHOOK_SECRET
    probe:
      - as: orders.count
        cmd: psql "$DATABASE_URL" -Atc "select count(*) from orders"
    reset: npm run db:reset:webhooks
    ```

    `secret` names an environment variable; the value never goes in the file. `probe` and `reset` are optional but turn on the state checks (Level 2). See [Configuration](/reference/configuration).

    Start the agent from the same directory, with the secret in its environment:

    ```bash
    export STRIPE_WEBHOOK_SECRET=whsec_...
    npx @webhooktrap/agent@1 agent
    ```
  </Step>

  <Step title="Start a run">
    Select a delivery in **Arrivals** and press **Prove**, or **Prove group** to take every event of the group.

    <Frame caption="Prove one delivery, or the whole group.">
      <img src="/images/prove-group-button.webp" alt="The Prove and Prove group buttons on a delivery, Prove group framed." />
    </Frame>

    Check the scenarios (1), the agent and target (2), and press **Run** (3).

    <Frame caption="The run draft.">
      <img src="/images/run-draft.webp" alt="Prove page with the scenario checklist, the connected agent and its target, and the Run button, numbered 1 to 3." />
    </Frame>

    The first time, the agent asks in your terminal before it sends anything:

    ```text
    Run from the browser
      server     https://app.webhooktrap.dev
      workspace  Account workspace · Maya Demo
      requested  Account workspace · Maya Demo
      target     http://127.0.0.1:4242/webhooks/stripe
    This run sends the same events several times. If your handler sends emails or charges cards, honour the Webhooktrap-Dry-Run header first.
    Allow runs started from the browser to send to this target? [y/N] y
    ```

    If `webhooktrap.yml` has `cmd:` probes or a `reset`, it lists those commands and asks once more.
  </Step>

  <Step title="Read the finding">
    The run page fills in as deliveries complete. The verdict line counts Critical, High and Medium findings and shows the exit code CI would get.

    <Frame caption="The verdict and the scenario strip of a finished run.">
      <img src="/images/run-result.webp" alt="Run page with 2 findings, exit 1, and one cell per scenario." />
    </Frame>

    Each finding says what happened, why it matters for this provider, and what to change. The fix names the deliveries that should behave differently on the next run.

    <Frame caption="F1: the handler accepted a body it should have rejected.">
      <img src="/images/finding-detail.webp" alt="Critical finding Accepts tampered payload with What happened, Why it matters, Likely cause, Fix and an Express snippet." />
    </Frame>
  </Step>
</Steps>
